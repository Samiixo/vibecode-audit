# ✅ vibe-audit: чек-лист перед деплоем

То, что сканер увидеть не может — проверь руками. Отметь каждый пункт перед продом.

## Деньги и лимиты (самое частое, что убивает вайбкод-проекты)
- [ ] В консоли OpenAI/Anthropic выставлен **spending limit** (жёсткий потолок трат)
- [ ] На AI-эндпоинтах стоит rate limit НА ПОЛЬЗОВАТЕЛЯ, не только глобальный
- [ ] У платных API задан `max_tokens` и лимит длины входного текста
- [ ] Настроены алерты на аномальный расход (billing alert в облаке)

## Доступы и права
- [ ] Все ключи, которые хоть раз были в git, **перевыпущены**
- [ ] Продовые и тестовые ключи — разные
- [ ] 2FA включена на GitHub, облаке, платёжках, домене
- [ ] Права сервисных аккаунтов урезаны до минимума (не «owner» на всё)
- [ ] Никто из бывших коллаборантов не остался с доступом

## База данных
- [ ] Supabase: RLS включён на КАЖДОЙ таблице + прогнан Dashboard → Advisors → Security
- [ ] Firebase: правила не `allow read, write: if true`
- [ ] Есть автоматические бэкапы, и ты хоть раз проверял, что восстановление работает
- [ ] БД не смотрит портом в интернет

## Приложение
- [ ] Каждый эндпоинт, который пишет/удаляет данные, проверяет авторизацию
- [ ] Пользователь A физически не может открыть данные пользователя B (проверь руками с двух аккаунтов)
- [ ] Валидация пользовательского ввода на сервере, а не только на клиенте
- [ ] Ошибки не вываливают стектрейсы и внутренности наружу
- [ ] Загрузка файлов ограничена по типу и размеру

## Инфраструктура
- [ ] HTTPS везде, HTTP редиректит на HTTPS
- [ ] Security-заголовки на месте (прогони livecheck.py по своему домену)
- [ ] `.env`, `.git`, дампы, бэкапы недоступны из браузера (livecheck это проверит)
- [ ] Логи не пишут секреты и токены

## CI/CD и автоматизация (добавлено в v2.0)
- [ ] Ни один workflow не делает `pull_request_target` + checkout чужой ветки
- [ ] Секреты не печатаются в лог: нет `echo ${{ secrets.* }}` в `run:`
- [ ] У каждого workflow минимальный `permissions:` (не `write-all` по умолчанию)
- [ ] Self-hosted раннеры не используются на публичных репозиториях
- [ ] `uses:` закреплены на теге или SHA, а не на `main`
- [ ] `dependabot` / автообновление зависимостей включено

## Контейнеры и инфраструктура (добавлено в v2.0)
- [ ] В production-образе нет `privileged: true` и `network_mode: host`
- [ ] Dockerfile задаёт непривилегированного `USER`
- [ ] Нет `curl … | bash` в `RUN` и `ADD <url>`
- [ ] Образы закреплены на конкретном теге или по digest, не `:latest`
- [ ] В `ENV`/`ARG`/`--build-arg` нет секретов (значение `ARG` видно в истории образа)
- [ ] `terraform.tfvars` не в репозитории; состояние — в удалённом хранилище с шифрованием
- [ ] Порты БД не опубликованы наружу

## Конфиги агентов и MCP (добавлено в v2.0)
- [ ] В `.mcp.json` / `mcp_settings.json` / `cline_mcp_settings.json` нет буквальных секретов
- [ ] У MCP-серверов ключи берутся из окружения, а не из файла в репозитории
- [ ] Агенты, которым выдан доступ, пересмотрены: у каждого — минимальные права

## Если что-то уже утёкло
- [ ] Ключ перевыпущен, старый отозван (перевыпуск важнее чистки истории)
- [ ] История почищена (`git filter-repo`), но это **не** отменяет пункт выше
- [ ] Проверен биллинг за период с момента коммита ключа
- [ ] Проверено, не утёк ли ключ через кеш сборок, логи CI и переменные окружения
