Found a live key? This is the order

the only order that helps
01 · RIGHT NOW

Rotate the key

In the provider's console. Not in the next sprint — now. A key that ever touched git is already compromised, even in a private repo: bots scan public repos continuously, and a private one goes public through one fork.

openai → platform → API keys → revoke
→
02 · THEN

Remove it from the code

Environment variable or secret manager. The public prefixes (NEXT_PUBLIC_, VITE_, REACT_APP_, PUBLIC_, EXPO_PUBLIC_) are for non-secret values only — they put the variable straight into the client bundle.

.env + .gitignore
→
03 · LAST

Clean the history

git filter-repo removes the string from commits, but it does not un-leak it. Step 01 is what actually protects the account; this one only stops the next person from finding it.

git filter-repo --path … --invert-paths

The scanner proves

a key-shaped literal exists in a file it read
that file is tracked by git
a config opens CORS / debug / TLS verification
an AI route has no auth keyword and no token cap
a workflow checks out a PR ref with repo secrets in scope

The scanner cannot prove — say so out loud

whether the key was ever valid, or is still active
whether a resource id is checked against its owner
RLS policies, cloud-console rights, infra, mobile apps
files skipped as too large, tools that could not run
anything requiring two real accounts and real traffic
A skipped check is not a green tick. "No findings" is a statement about the files that were read.
