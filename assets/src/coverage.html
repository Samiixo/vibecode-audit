What v2.0 covers

v1 checks + the modern attack surface

Secrets & keys v1 + v2

  • 30+ providers: OpenAI, Anthropic, AWS, Stripe, Supabase, GitHub, GitLab, npm, Cloudflare, Vercel, HF, Groq…
  • project keys, webhooks, JWT literals, Azure connection strings
  • files v1 never opened: Dockerfile, *.tfvars, .npmrc, .pem, .netrc, Procfile
  • public env prefixes: NEXT_PUBLIC_, VITE_, REACT_APP_
  • Astro PUBLIC_, SvelteKit $env/static/public, EXPO_PUBLIC_
  • MCP configs with literal secrets in env

Infrastructure new in v2

  • TLS off: verify=False, rejectUnauthorized, NODE_TLS_REJECT_UNAUTHORIZED=0
  • pull_request_target + checkout of a PR ref
  • secrets echoed in run:, permissions: write-all, self-hosted runners
  • privileged: true, root container, curl | bash, ADD <url>, :latest
  • secrets in ENV / ARG / --build-arg
  • postinstall scripts, git-URL dependencies, missing lockfile

Code-level risk v1 + v2

  • SQL via f-string, CORS *, debug on, eval
  • command injection, os.system, pickle, unsafe yaml, zip-slip, SSTI, NoSQL $where
  • SSRF from request input; dangerouslySetInnerHTML with user data
  • Math.random() OTP, md5/sha1 passwords, jwt.decode as verify, alg confusion
  • hardcoded AUTH_SECRET fallback, auth token in localStorage
  • role from client, IDOR, no rate limit, open AI endpoint, missing max_tokens
Severity means certainty, not suspicion. critical = unambiguously wrong (a live key, privileged: true, secrets echoed in CI) · warning = reads wrong, fix it · info = «needs a human look» — an honest "I couldn't prove it from code". A noisy linter gets deleted by its users, so every heuristic that cannot be made precise is downgraded, not kept loud.
